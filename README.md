# 风水审查 Skill（fengshui-audit）

## 这是什么？能帮我做什么？

一句话：**把你家的户型交给它，它会像一位懂建筑的老师傅一样，逐条告诉你——床头没靠墙、门一开正对着卫生间、灶台离水槽太近……每一处都给出"现状实测值、为什么要改、具体怎么改"。**

- **输入**：一份描述户型的 JSON（墙在哪、门在哪、床和沙发摆在哪、朝向如何）
- **输出**：一份问题清单，按严重程度分级，附调整建议
- **改完之后**：再跑一遍，它会告诉你哪些问题解决了、哪些还在、有没有改出新问题

它**不算命**。传统风水里"床头靠实墙""开门见灶"这些说法，背后其实是睡得稳不稳、动线顺不顺、干湿能不能分开的空间问题。本项目把 20 条这类说法**翻译成了能量出来的几何规则**（比如"床头离墙不能超过 5 厘米""开门视线 30° 锥形范围内不能正对床"），所以：

- 每一条结果都**可复现、可验证**——同一份户型跑两次，结果一定一样
- 每一条建议都**标明依据来源**——是古籍原文、国家标准，还是项目自定的工程参考值，绝不含糊、绝不把没核实的内容冒充"古书说的"
- 吉凶断言、生辰八字合婚这类无法验证的内容**明确排除**在判定之外（命卦仅作为默认关闭的可选文化参考模块）

真实输出长这样（示例户型埋了 9 处问题，全部命中）：

```markdown
## 🔴 FS-BED-001 床头靠实墙
- 现状：床头边距最近实墙 0.85 m，超过贴墙阈值 0.05 m
- 建议：将 次卧床 床头旋转至紧邻实墙，贴合 0.05 m 以内。

## 🔴 FS-KIT-001 灶台-水槽间距过近（「水火不相冲」几何转译）
- 现状：灶台与水槽最小间距 0.15 m，低于 0.60 m
- 建议：拉开灶台与水槽间距至 ≥ 0.60 m，或中间插入操作台。

## 🔴 FS-ENT-001 大门对卫生间门
- 现状：入户门与卫生间门相对，中心距 2.60 m（阈值 3.00 m）
- 建议：卫生间常闭门，或加设玄关隔断/门帘。
```

适用场景：装修前的户型自查、家具摆放调整、室内设计工具的规则引擎、以及想把传统居住智慧做成**可验证产品**的开发者。

---

家居布局的风水审查 Skill：把 20 条形法条目**转译成可几何判定的规则**，输入一份 2D 户型 JSON，输出结构化的违规清单与调整建议。

属于 **Immerse·Home** 项目（毛坯房 AR 沉浸式家居系统）的审查模块。

## 它解决的问题

传统风水条目的表述是"床头不宜靠窗""开门见灶，钱财多耗"这类**定性描述**，机器判不了、设计师也没法照着改。本项目做的是把每条条目拆成三样可执行的东西：

| 层 | 职责 | 产物 |
|---|---|---|
| L1 规则引擎 | 几何判定，输出"哪条规则、命中哪些对象、实测值多少" | `scripts/check.py` |
| L2 知识层 | 规则库覆盖不到时的解释与兜底（RAG） | 提示词，接入侧实现 |
| L3 表达层 | 把违规 JSON 转成分级语气的用户话术 | `references/output-style.md` |

## 快速开始

无需安装依赖，Python 3.9+ 标准库即可运行。

```bash
# 自检：demo 埋了 9 处问题，应命中 9 条
python scripts/check.py --scene assets/demo_scene.json --format md

# 复检：这些问题改完后应只剩 1 条
python scripts/check.py --scene assets/demo_scene_fixed.json --format md

# 列出全部规则
python scripts/check.py --list

# 可选：启用八宅派命卦文化参考（默认关闭，不影响 20 条判定）
python scripts/check.py --scene assets/demo_scene.json --culture --format md

# JSON 输出（供上层程序消费）
python scripts/check.py --scene assets/demo_scene.json
```

**改动任何阈值或判定逻辑后，必须跑上面这一对场景。** 数字从 9/1 变了，说明改过头了。

剩下那条无法消除的是「入户门正对卫生间门」——建筑门位问题，挪家具解决不了。这是有意保留的：引擎会如实说"这条得改门"，不会假装一键搞定。

## 输入格式

一份 JSON 描述户型：墙体（区分实墙/窗墙）、门（含入户门朝向）、房间、家具（旋转矩形：中心、长、宽、朝向）、梁。完整字段见 `references/scene-schema.md`。

```json
{
  "rect": { "cx": 1.6, "cy": 2.4, "len": 0.9, "wid": 2.2, "heading": 0 }
}
```

注意语义：`len` 沿 `heading` 方向（**进深**），`wid` 为垂直方向（**面宽**）。沙发这类家具填反不会报错，但形状会横过来。

## 出处与可信度

`references/evidence.md` 按核对状态分三级标注，**不做美化**：

- ✅ 已核到原书具体页码
- ⚠️ 有书，具体页码未核
- 🔶 二手转引，原始出处待核

当前 20 条中，5 条具体页码未核，《阳宅三要》《鲁班经》两条属二手转引。这是已知缺口，不是遗漏——被问到时应当如实回答"这条还没核到原书"，而不是含糊带过。

## 关于"转译"的说明

部分条目原文讲的是**方位**，实现时转成了**几何关系**。典型例子是「厨灶必须居左位，不宜安在白虎方」：原典的"左/白虎方"是相对坐向的方位概念，本项目转译为"灶与水槽的操作间距"，并保留双属性标注 `ergonomic+culture`。

**这是几何可判定转译，不是直译。** 引用时须说明这层关系，否则容易被指为曲解原典。

## 关于生辰八字（可选模块）

风水常被追问"不用合八字吗"。这块做成了**默认关闭的独立模块**，不混进 20 条判定。

启用后做的是：按**八宅派**约定，用出生年份算命卦（含 5 黄男寄坤/女寄艮、立春近似校正），
与宅向比对，得出"命与宅是否同组"。结果写在 `culture_reference` 字段。

刻意不做的四件事，比做了什么更重要：

- **不进 `violations`**，不计入"9 条需要调整"这类统计
- **不生成改动建议**，不会出现"床头转向X方以合命卦"
- **不做吉凶断言**，只说"该派认为相配/不相配"
- **不隐藏局限**，四条局限随结果一起输出，不靠提示词"记得说"

切开的理由：这 20 条每条都能用国标或人体工程学撑起第二条腿，命卦撑不起来。掺在一起，
被问"这不就是算命吗"的时候，前面 20 条的论证会被一起拖下水。分开摆反而是加分项——
可以主动说"我们区分了可验证的空间约束与不可验证的文化解释"。

出处状态：🔶 **二手转引**。八宅派命卦说通常归于《八宅明镜》，本仓库未收录该书，
算法依据是通行命卦表。引用时说"据八宅派通行说法"，**不要报书名页码**。详见 `references/minggua.md`。

## 已知局限

详见 `SKILL.md`。`DIST_CORRIDOR_MIN = 0.90 m` 已对齐 GB 55038-2025 通厨卫强制下限；
注意通卧室/起居室的通道国标要求 1.00–1.10 m，本规则不区分通道去向。
