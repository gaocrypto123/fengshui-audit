# fengshui-audit · 房屋风水 + 国标双重检测 Skill

## 这是什么？能帮我做什么？

一句话：**把你家的户型交给它，它会用「两把尺子」给房子做体检——一把是传统风水的居住经验，一把是国家标准的强制条文。床头没靠墙、门一开正对卫生间、灶台离水槽太近、门宽不够国标下限……每一处都告诉你"现状实测值、为什么要改、具体怎么改"。**

- **输入**：一份描述户型的 JSON（墙在哪、门在哪、床和沙发摆在哪、朝向如何）
- **输出**：一份问题清单，按严重程度分级，附调整建议和**依据来源**
- **改完之后**：再跑一遍，它会告诉你哪些问题解决了、哪些还在、有没有改出新问题

## 两把尺子是什么？

普通风水工具只有"风水"一条腿，被问"这不就是迷信吗"就哑火。本项目的 **21 条规则**每条至少站一条腿，多数站两条：

| 尺子 | 管什么 | 例子 |
|---|---|---|
| **🧭 国标（GB 55038-2025 / GB 50096-2011）** | 强制底线：门净宽、过道净宽、厨卫关系 | 户门通行净宽 ≥ 0.90 m、卧室门 ≥ 0.80 m、厨卫门 ≥ 0.70 m（GB 55038-2025 4.1.14，**已核验到印刷页码**） |
| **📖 风水典籍（阳宅十书、黄帝宅经等）** | 传统居住经验：床头靠实墙、开门不见灶、明堂开阔 | "开门见灶，钱财多耗"转译为"入户门视线 30° 锥内不应正对灶台" |

两把尺子**严格分开记账**：国标条文直接给判定阈值（`national_standard` 层）；风水主张逐条登记核对状态——核到原书页码的标 ✅，没核到的如实标 ⚠️/🔶，**绝不拿国标冒充"古书说的"，也绝不拿没核实的说法冒充典籍原文**。

它**不算命**。吉凶断言、生辰八字合婚这类无法验证的内容明确排除在判定之外（命卦仅作为默认关闭的可选文化参考模块）。

## 真实输出长这样

示例户型埋了 9 处问题，全部命中（demo 回归锁）：

```markdown
## 🔴 FS-BED-001 床头靠实墙
- 现状：床头边距最近实墙 0.85 m，超过贴墙阈值 0.05 m
- 建议：将 次卧床 床头旋转至紧邻实墙，贴合 0.05 m 以内。

## 🔴 FS-KIT-001 灶台-水槽间距过近（「水火不相冲」几何转译）
- 现状：灶台与水槽最小间距 0.15 m，低于 0.60 m
- 建议：拉开灶台与水槽间距至 ≥ 0.60 m，或中间插入操作台。

## 🔴 FS-GEN-005 门通行净宽分级
- 现状：「卫生间门」宽 0.65 m，低于 厨房/卫生间门下限 0.70 m
  （GB 55038-2025 4.1.14，按洞口宽保守近似，复检应实测通行净宽）
- 建议：换门或调整门洞（改洞口需结构复核），使户门 ≥ 0.90 m、
  卧室门 ≥ 0.80 m、厨卫门 ≥ 0.70 m。
```

每条违规都能附加**机器可读的证据链**（`chain` 字段）：主张原文出处、阈值来源（四层标注：国标 / 已核参考值 / 项目自定 / 几何一致性）、条文号页码、复检验收标准——「原页 → 主张 → 阈值 → 判定 → 建议 → 复检」全程可追溯。

适用场景：装修前的户型自查、家具摆放调整、室内设计工具的规则引擎、以及想把传统居住智慧做成**可验证产品**的开发者。

---

属于 **Immerse·Home** 项目（毛坯房 AR 沉浸式家居系统）的审查模块。

## 它解决的问题

传统风水条目是"床头不宜靠窗""开门见灶，钱财多耗"这类**定性描述**，机器判不了、设计师也没法照着改；国标条文是"门净宽不应小于 0.90 m"这类**强制底线**，普通人不知道自己家达不达标。本项目把两者都拆成可执行的东西：

| 层 | 职责 | 产物 |
|---|---|---|
| L1 规则引擎 | 几何判定（风水转译规则 + 国标分级规则），输出"哪条规则、命中哪些对象、实测值多少" | `scripts/check.py` |
| L2 知识层 | 规则库覆盖不到时的解释与兜底（RAG） | 提示词，接入侧实现 |
| L3 表达层 | 把违规 JSON 转成分级语气的用户话术 | `references/output-style.md` |

## 快速开始

无需安装依赖，Python 3.9+ 标准库即可运行。

```bash
# 自检：demo 埋了 9 处问题，应命中 9 条
python scripts/check.py --scene assets/demo_scene.json --format md

# 复检：这些问题改完后应只剩 1 条
python scripts/check.py --scene assets/demo_scene_fixed.json --format md

# 列出全部规则
python scripts/check.py --list

# 可选：启用八宅派命卦文化参考（默认关闭，不影响 21 条判定）
python scripts/check.py --scene assets/demo_scene.json --culture --format md

# JSON 输出（供上层程序消费）
python scripts/check.py --scene assets/demo_scene.json
```

**改动任何阈值或判定逻辑后，必须跑上面这一对场景。** 数字从 9/1 变了，说明改过头了。

剩下那条无法消除的是「入户门正对卫生间门」——建筑门位问题，挪家具解决不了。这是有意保留的：引擎会如实说"这条得改门"，不会假装一键搞定。

## 输入格式

一份 JSON 描述户型：墙体（区分实墙/窗墙）、门（含入户门朝向与门宽 `width`）、房间、家具（旋转矩形：中心、长、宽、朝向）、梁。完整字段见 `references/scene-schema.md`。

```json
{
  "rect": { "cx": 1.6, "cy": 2.4, "len": 0.9, "wid": 2.2, "heading": 0 }
}
```

注意语义：`len` 沿 `heading` 方向（**进深**），`wid` 为垂直方向（**面宽**）。沙发这类家具填反不会报错，但形状会横过来。

## 出处与可信度：三层证据隔离

这是本项目与普通风水工具的根本区别。所有证据登记在 `references/evidence-registry.json`，**三层严格隔离、互相不冒充**：

| 层 | 内容 | 状态 | 用途 |
|---|---|---|---|
| `verified_design_bases` | 国标条文 + 人体工程学 + 设计书尺寸 | **verified**（已核验到印刷页码 + 书籍 SHA-256 指纹） | 直接给规则阈值（如门宽、过道、床侧通道） |
| `claims` | 8 条风水主张 | **pending**（逐主张逐页核对中） | 决定风水规则 citation_status |
| `classical_backgrounds` | 典籍背景（阳宅六事、反光煞、门不相对等） | **secondary_unverified**（定位到书但未逐字核验） | 文化解释，不进判定 |

**为什么隔离**：国标依据只声明"这个阈值有出处"，**不提升**风水主张的验证状态——"门宽 0.70 有 GB 55038 背书"和"开门见灶主耗财被典籍证明"是两件事，混在一起就是伪造。测试固化了这条红线（`tests/test_reasoning.py` ThresholdSourceTests：凡标 national_standard 的阈值必须指向真实存在且已核验的国标条目）。

`references/evidence.md` 按核对状态分三级标注，不做美化：✅ 已核到原书具体页码 / ⚠️ 有书，页码未核 / 🔶 二手转引待核。

## 参考资料：这个 Skill 背后的书单

规则依据不是拍脑袋来的。项目收录 **9 份参考资料**，每份都登记了总页数、可提取文字页数和 SHA-256 文件指纹（锁定版本、防止混用不同版次），登记表见 `references/book-inventory.json`：

| 类别 | 资料 | 在项目里的角色 |
|---|---|---|
| **国家标准** | GB 50096-2011《住宅设计规范》 | 厨房净距、卫生间门、门洞尺寸等强制下限 |
| **国家标准** | GB 55038-2025《住宅项目规范》（全文强制） | 过道净宽（4.1.13）、门净宽分级（4.1.14）等**已核验并直接驱动判定** |
| **人体工程学** | 《人体工程学图解——设计中的人体因素》 | 床边通道、床前空间、厨房走道等**物理阈值**（914/1219/1220 mm，已核验） |
| **室内设计** | 《住宅设计解剖书》（增田奏） | 床侧通道 MIN.450 等功能布局尺寸（已核验） |
| **室内设计** | 《室内设计资料集》（张绮曼） | 空间尺度与家具布置的行业参考 |
| **风水典籍** | 《图解阳宅十书》 | 形法条目的主要典籍来源 |
| **风水典籍** | 《图解黄帝宅经》 | 宅经类条目的典籍来源（阳宅六事、反光煞） |
| **学术研究** | 《风水探源》（何晓昕） | 风水空间观念的溯源与解读（门不相对原则） |
| **学术研究** | 《风水理论研究》第 2 版（王其亨主编） | 学院派对风水空间规则的研究整理 |

全部 9 份资料已完成 OCR 逐项核对（核对方法与结果见 `references/evidence-registry.json` 各条目的 `verification` 字段）。

**诚实声明**：多数典籍为扫描版，无法全文检索，项目采用「逐主张逐页核对」建立引用——每条引用登记书籍指纹、版本、PDF 物理页 + 印刷页、原文摘录、支持的主张和核对人。**没有核对完成的内容，本项目绝不声称"原书证明"。** OCR 核对发现的最重要的真相也如实记录：典籍讲的多是**方位吉凶**，而本项目判定的是**几何间距**——「关注什么」来自典籍，「多少毫米」来自国标与人体工程学，这层转译关系在每条规则的证据链里都有标注。

## 关于"转译"的说明

部分条目原文讲的是**方位**，实现时转成了**几何关系**。典型例子是「厨灶必须居左位，不宜安在白虎方」：原典的"左/白虎方"是相对坐向的方位概念，本项目转译为"灶与水槽的操作间距"，并保留双属性标注 `ergonomic+culture`。

**这是几何可判定转译，不是直译。** 引用时须说明这层关系，否则容易被指为曲解原典。

## 阈值来源四层标注

每条规则的阈值来源在 `references/rule-chain.json` 里分四层标注，不装门面：

- **national_standard**：直接引用已核验国标条文（含条文号/页码/书籍指纹链）
- **book_ergonomics_referenced**：项目自定值 + 已核验参考值如实并列（如床侧通道 0.60 m，旁注解剖书最低 450 / 人机舒适 914）
- **project_convention**：项目几何转译值，无书籍或国标出处（如灶-门 0.90 m，并显式声明与 GB 50096 5.3.5 设备净距"数值巧合但语义不同、不得引用"）
- **geometry_consistency**：几何一致性检查，无独立数值阈值

## 关于生辰八字（可选模块）

风水常被追问"不用合八字吗"。这块做成了**默认关闭的独立模块**，不混进 21 条判定。

启用后做的是：按**八宅派**约定，用出生年份算命卦（含 5 黄男寄坤/女寄艮、立春近似校正），与宅向比对，得出"命与宅是否同组"。结果写在 `culture_reference` 字段。

刻意不做的四件事，比做了什么更重要：

- **不进 `violations`**，不计入"9 条需要调整"这类统计
- **不生成改动建议**，不会出现"床头转向X方以合命卦"
- **不做吉凶断言**，只说"该派认为相配/不相配"
- **不隐藏局限**，四条局限随结果一起输出，不靠提示词"记得说"

切开的理由：这 21 条每条都能用国标或人体工程学撑起第二条腿，命卦撑不起来。掺在一起，被问"这不就是算命吗"的时候，前面 21 条的论证会被一起拖下水。分开摆反而是加分项——可以主动说"我们区分了可验证的空间约束与不可验证的文化解释"。

出处状态：🔶 **二手转引**。八宅派命卦说通常归于《八宅明镜》，本仓库未收录该书，算法依据是通行命卦表。引用时说"据八宅派通行说法"，**不要报书名页码**。详见 `references/minggua.md`。

## 已知局限

详见 `SKILL.md`，摘要：

- 国标门宽判定的口径是「场景 width（洞口宽）≥ 净宽下限」的保守近似，复检应实测通行净宽（扣门扇开启占位）
- `DIST_CORRIDOR_MIN = 0.90 m` 采用 GB 55038-2025 通厨卫最低档；通卧室/起居室国标要求 1.00–1.10 m，复检按实际用途档
- 风水主张的逐页核对仍在进行（`claims` 层 pending），未核到的说法如实标注，不冒充已验证
- 古书流派分歧按登记表**并列呈现**、不裁决（如床位吉方的八宅与玄空两派说法）；登记表之外的新冲突自动发现尚未实现
